# Kestrel: домашнее задание по обучению LLM

Если вы здесь впервые, сначала откройте [`START_HERE.md`](START_HERE.md): там коротко, что за задача. Здесь собраны практические вещи: что дописать, как запустить и что сдать.

Речь о маленькой MoE-модели **Kestrel-22M-A4M** (decoder-only, Pre-RMSNorm, GQA с QK-Norm, RoPE/YaRN, 8 SwiGLU-экспертов с top-2, 22 303 488 параметров). Вам нужно дописать ключевые места в её коде, прогнать публичные тесты у себя, а потом запустить один ноутбук в Google Colab на T4. Претрейн мы уже сделали, два чекпоинта (AdamW и Muon) лежат на Hugging Face. Ноутбук проверит, что они нормально грузятся в вашу модель, а затем дообучит их на длинном контексте с YaRN по схеме 2 на 2 (чем предобучали и чем дообучаем), построит графики и запишет `results.json`.

## Что надо дописать

Пять файлов, в которых стоит `raise NotImplementedError("TODO: ...")`. Всё остальное устроено так: формулы и пошаговые планы лежат в техническом отчёте [`TECH_REPORT.md`](TECH_REPORT.md) (разделы 2 и 4 и приложение A, там же ссылки на нужные файлы), а docstring'и в коде описывают только интерфейс: формы, типы и что возвращать. Читайте отчёт и по ходу дела пишете код и заполняете пропуски **[ЗАПОЛНИТЬ]**.

| Файл | Что реализовать |
| --- | --- |
| `kestrel/model/yarn.py` | `yarn_inv_freq`, `yarn_mscale` |
| `kestrel/model/attention.py` | `expand_kv`, `GQAttention.forward` (GQA, QK-Norm, RoPE со смещением, KV-кэш) |
| `kestrel/model/moe.py` | `route`, `switch_aux_loss`, `MoE.forward` |
| `kestrel/optim/adamw.py` | `AdamW.step` |

Остальной код (модель, Muon, расписание, данные, тренер, оценка, графики) готов. Пробегитесь по нему глазами, на это уйдёт около часа. `configs/kestrel.yaml` менять нельзя: ноутбук проверяет его хеш.

## Как начать

1. Распакуйте выданный архив и откройте папку проекта в терминале.
2. Поставьте пакет:

```bash
pip install -e .
```

3. Гоняйте тесты по мере продвижения (на CPU это меньше минуты):

```bash
pytest -m "not slow"
```

Удобный порядок: `yarn`, потом `attention`, `moe`, `adamw`, `param_groups`. Пока функции не написаны, тесты падают с `NotImplementedError`, это нормально. Полный набор вместе с медленными тестами (маленькая модель переобучается на одном батче) запускается просто `pytest`.

## Запуск в Colab

1. Откройте `notebooks/kestrel_hw.ipynb` в Colab и включите T4: Runtime → Change runtime type → **T4 GPU**.
2. Когда тесты зелёные, упакуйте папку проекта в zip. На Windows это правый клик, «Отправить», «Сжатая ZIP-папка»; в терминале можно так: `zip -r kestrel-hw.zip kestrel-hw`. Виртуальное окружение (`venv`) и скачанные данные в архив класть не надо. Назовите его `kestrel-hw.zip` и положите на Google Drive в `MyDrive/kestrel_hw/kestrel-hw.zip`: тогда он переживёт обрыв сессии. Если архива нигде не окажется, первая ячейка сама откроет окно загрузки файла. Ноутбук распаковывает архив заново при каждом запуске, так что после правок кода достаточно заменить архив и перезапустить первую ячейку.
3. Запускайте ячейки по порядку. Ноутбук подключит Google Drive, скачает данные и два чекпоинта и всё сохранит в `MyDrive/kestrel_hw/`. Colab-часть (четыре дообучения и оценки) занимает 40–60 минут. Если сессия оборвётся, запустите ноутбук ещё раз: законченные секции пропустятся, а незаконченные продолжатся с последнего чекпоинта (они сохраняются каждые 100 шагов).

   Сразу после скачивания ноутбук **сверяет val loss выданных чекпоинтов с нашим**. Если не совпало, в вашем коде сидит ошибка, которую тесты не поймали, подсказки в приложении A.7 отчёта. Если во время дообучения вылезло предупреждение о медленном шаге, проверьте, что внимание считается через `F.scaled_dot_product_attention` (приложение A.2).
4. Хотите быстро убедиться, что ноутбук вообще работает? Поставьте `SMOKE = True` в первой ячейке. Весь пайплайн пройдёт на CPU на крошечных синтетических данных за пару минут. Это только проверка, для сдачи такие числа не годятся.
